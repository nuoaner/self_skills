# Market Manager Commercialization Playbook

This playbook is the heavy reference for market-manager thinking. Use it when the user asks for deep commercialization, market strategy, product positioning, user attraction, retention, pricing, launch, or commercial maturity work.

## Core Principle

A mature commercial project does not only "look good". It must create a clear promise, solve a real problem, earn trust, fit a repeatable workflow, support a buyer's decision, and provide enough operational maturity to be sold, delivered, supported, and improved.

## 1. Fast Diagnosis

Use this first when context is limited.

| Question | Good Signal | Weak Signal |
|---|---|---|
| Who is the target user? | Specific role, scenario, pain, urgency | "Everyone can use it" |
| What outcome is promised? | Clear before/after improvement | Feature list only |
| Why now? | Timing, regulation, technology, market pressure | No urgency |
| Why this product? | Differentiated workflow, data, quality, trust, cost, or speed | Same as competitors |
| Why pay? | Saves money, makes money, reduces risk, increases speed, or improves status | "It is convenient" only |
| Why stay? | Recurring workflow, saved data, collaboration, habit, integration, service reliability | One-time novelty |

## 2. User Attraction

Design the first impression around one concrete promise.

Strong attraction usually comes from:

- Pain relief: remove a repeated frustration.
- Gain creation: help users earn more, move faster, look better, or decide better.
- Risk reduction: avoid mistakes, missed deadlines, compliance issues, or operational uncertainty.
- Identity value: make users feel professional, capable, modern, safe, or in control.
- Curiosity gap: show a surprising before/after, benchmark, score, or diagnosis.

Avoid vague promises such as "smart", "efficient", "all-in-one", or "empowering" unless they are tied to a measurable outcome.

## 3. User Love

Users like products that repeatedly make them feel progress.

Look for:

- Aha moment: the first moment the user clearly sees value.
- Low-friction start: the user reaches value without configuration fatigue.
- Feedback loops: the product shows progress, saved time, improved quality, or risk reduced.
- Taste and care: wording, empty states, guidance, and defaults feel intentional.
- Personal relevance: the product adapts to the user's role, data, project, or workflow.

Good product emotion is not decoration. It is the feeling of "this understands my problem".

## 4. Ethical Retention and Dependency

Build dependency through value compounding, not coercion.

Healthy dependency patterns:

- Data accumulation: reports, history, assets, templates, preferences, or project memory become more useful over time.
- Workflow integration: the product fits a repeated daily, weekly, or monthly job.
- Collaboration graph: teammates, clients, reviewers, or stakeholders coordinate through the product.
- Habit trigger: the user naturally returns at a specific moment, such as planning, publishing, reviewing, reporting, or handoff.
- Switching cost through quality: users stay because migration would lose context, not because export is blocked.
- Trust loop: consistent reliability, support, and transparent changes make the product safer to keep using.

Do not recommend dark patterns:

- Hidden cancellation.
- Data hostage behavior.
- Fake scarcity.
- Forced virality.
- Misleading pricing.
- Artificial friction that only traps users.

## 5. Market Fit

Evaluate market fit through the pain-buyer-budget triangle.

Pain:

- Is the problem frequent, expensive, risky, embarrassing, or strategically important?
- Does the user already spend time or money solving it?
- Is there an obvious trigger event that makes the user seek a solution?

Buyer:

- Is the buyer the same as the user?
- If not, what does the buyer care about: cost, risk, revenue, control, compliance, visibility?
- Who blocks adoption: IT, finance, legal, management, operations, end users?

Budget:

- Is the product replacing an existing tool, outsourcing cost, manual labor, or avoidable risk?
- Can value be expressed in money, time, conversion, retention, quality, or risk reduction?
- Is there a reasonable pricing anchor in the market?

## 6. Differentiation

Do not define differentiation as "more features". Use one or two clear axes.

Possible axes:

- Faster time to value.
- More specialized for a vertical user.
- Better workflow fit.
- Better data or memory.
- Better reliability or compliance.
- Better taste and user experience.
- Lower total cost.
- Stronger integration with existing tools.
- Better service, onboarding, or expert guidance.

Positioning formula:

```text
For [target user] who struggle with [urgent pain],
[product] is a [category] that helps them [measurable outcome],
unlike [alternative], it [main differentiator].
```

## 7. Commercialization Design

Commercial maturity requires the product and the business wrapper.

Minimum commercial package:

- Clear target customer.
- Clear category and positioning.
- Landing page or README that explains value quickly.
- Use cases and proof.
- Pricing or at least pricing direction.
- Onboarding path.
- Support path.
- Terms, privacy, and data handling notes when relevant.
- Feedback and iteration channel.
- Metrics for acquisition, activation, retention, revenue, and referral.

## 8. Pricing and Packaging

Choose pricing based on value capture and user expectation.

Common models:

- Free + paid upgrade: useful when adoption and habit matter.
- Subscription: useful for recurring workflows and continuous service.
- Usage-based: useful when cost and value scale with activity.
- Seat-based: useful for team collaboration tools.
- Project-based: useful for agencies, implementation, or consulting-heavy products.
- Enterprise license: useful when security, compliance, procurement, and support matter.

Package around outcomes, not internal features.

Example:

```text
Starter: prove value for one user or one project.
Pro: support repeated workflow, exports, advanced automation, and priority features.
Team: collaboration, permissions, shared assets, admin, and reporting.
Enterprise: security, compliance, SSO, custom support, SLA, and procurement.
```

## 9. Landing Page and README Conversion

A commercial-facing project page should answer these questions quickly:

- What is it?
- Who is it for?
- What painful job does it solve?
- What result can the user expect?
- Why is it different?
- How does the user start?
- What proof or trust signal exists?
- What should the user do next?

Recommended page structure:

```text
Hero: promise + target user + CTA
Problem: specific pain and current alternatives
Solution: how the product changes the workflow
Use cases: 3-5 concrete scenarios
Proof: screenshots, examples, benchmarks, testimonials, case notes, or demos
How it works: short workflow
Pricing or commercial path
FAQ: risk, compatibility, data, support, limits
CTA: start, install, book demo, contact, or join waitlist
```

## 10. Commercial Readiness Checklist

Score each item from 0 to 2.

| Area | 0 | 1 | 2 |
|---|---|---|---|
| Target user | Vague | Somewhat defined | Specific role and scenario |
| Pain | Assumed | Described | Validated or strongly evidenced |
| Value promise | Feature-based | Benefit-based | Outcome-based and measurable |
| Differentiation | None | Generic | Clear versus alternatives |
| Activation | Hard to start | Usable | Fast aha moment |
| Retention | One-off use | Some repeat use | Recurring workflow or compounding value |
| Monetization | None | Possible | Pricing path and buyer logic clear |
| Trust | Missing | Basic | Proof, support, data handling, credibility |
| Delivery | Manual or unclear | Partly defined | Repeatable onboarding and support |
| Metrics | None | Basic | Acquisition, activation, retention, revenue tracked |

Interpretation:

- 0-7: idea stage. Clarify user, pain, and value before scaling.
- 8-13: promising. Improve proof, activation, and differentiation.
- 14-20: commercialization-ready direction. Focus on launch, pricing, sales, and retention.

## 12. Practical Heuristics

- If the product cannot be explained in one sentence, the market will not understand it quickly.
- If the first-use path does not reveal value fast, acquisition spending will be wasted.
- If retention relies only on reminders, the product has not entered the user's workflow.
- If pricing is hard to justify, the value may not be tied to money, risk, time, or status strongly enough.
- If competitors are ignored, differentiation is probably imagined rather than real.
- If the product is useful but not trusted, add proof, transparency, support, and reliability before adding more features.
