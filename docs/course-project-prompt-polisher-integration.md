# 课程制作中使用 project-prompt-polisher 的约定

源 Skill：`skills/project-prompt-polisher/SKILL.md`。本文件是课程制作集成指南，**不改写或替代源 Skill**。

## 定位
在课件生产之前，将自然语言需求规范化为可执行任务单。后续由相应课程 Skill、文档/PPT 工具实施，避免把“润色需求”误当成“自动完成课程”。

## 课程需求规范化必填项
1. 教学对象：年龄/专业、先修基础、使用情境。
2. 教学目标：完成后学生能说清、操作或验证什么。
3. 课程范围：主题、课时、材料来源；区分必须覆盖和可选拓展。
4. 产出类型：教案、课堂 PPT、讲师备注、练习、实验或答案。
5. 教学路径：从已知到未知、概念—作用—机制—例子—练习。
6. 表达约束：左上角标题简短、术语首次出现需解释、去模板化表述。
7. 图示语义：组成关系、过程顺序、状态转换、反馈闭环分别画；箭头附清晰含义。
8. 页面密度：先覆盖知识再定页数；减少无效留白，不靠堆字充实。
9. 证据边界：技术版本和关键数据标注来源；不编造实验结果。
10. 验收：知识覆盖、单页可读性、准确性、讲授连贯性、图文对应、可编辑与渲染检查。

## 推荐流程
口头需求 → project-prompt-polisher 整理任务单 → 授课材料核对 → 课程 Skill 生产 → 内容/图示/版式验收 → 反馈迭代。

## 提示词模板
请根据以下口头需求，先整理课程制作任务单，**暂不直接制作 PPT**：

【原始需求】<用户原话>

输出：
- 已知事实与尚待确认项（不要猜测）。
- 教学对象、课时和可观察教学目标。
- 必讲知识点、讲解顺序、难点及实例。
- 课件/教案/练习等交付物与格式。
- 保留事项与不得改动的范围。
- 图示要求及每条流程箭头的语义。
- 验收清单和检查方法。

如用户要求直接制作课件，则在规范化需求后执行，不要因为本模板强制中断工作。
